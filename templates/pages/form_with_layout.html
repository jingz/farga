Six ways to arrange fields, then four forms assembled from them. Every demo is a real <form> inside .form, which caps the column at 36rem — so pressing Enter submits it, and in these docs that reloads the page with a query string.

Layout patterns

Farga styles a form from its elements, so a layout is a choice of wrapper around the field, not a class on the control.

Stacked — the default

One field per row, label above the control. Use it unless there is a reason not to: it survives long labels, long values, translation, and a 320px screen.

Field anatomy and errors

A field is a label, a control, and — when it needs one — a message that belongs to the control through aria-describedby. Required controls are marked by the required attribute alone: the asterisk comes from CSS, so it never carries the meaning on its own.

Summary when validation fails

Name the problem at the top of the form, link each item straight to its control, and let the alert announce itself with role="alert". The messages below the fields repeat the detail for anyone who arrives there directly.

Required, hint and error together

The asterisk is decorative — required is what assistive tech reports — and it depends on the label's shape, because CSS cannot follow a for attribute. The hint and the error differ by more than colour: one explains, the other says what went wrong.
